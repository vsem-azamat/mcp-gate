# Escrow and file scanning

[Docs](../README.md) / [Architecture](README.md) / **Escrow and file scanning**

The escrow keeps redacted secrets in memory so that the owner can release them, and file scanning withholds downloaded files that hold secrets. The behaviour is specified in [`openspec/specs/escrow/spec.md`](../../openspec/specs/escrow/spec.md) and [`openspec/specs/file-scanning/spec.md`](../../openspec/specs/file-scanning/spec.md).

## Wiring

`cmd/mcp-gate serve` and `check` call `escrow.ResolveKey` ([`key.go`](../../internal/escrow/key.go)) with the config's `escrow.keyHash` or `escrow.keyHashFile` and the environment: it parses every source that is set (the file is opened once, checked with `fstat` and read up to 1 KiB), fails when two disagree, and returns the hash with the name of the source that wins (config, `MCP_GATE_ESCROW_KEY_SHA256`, then the deprecated `MCP_HUB_ESCROW_KEY_SHA256`). `serve` logs the deprecation warning, strips both variables from the environment the children inherit from, and passes the `escrow.Key` as `gate.Options.EscrowKey`. `gate.New` then builds one `escrow.Escrow` and mounts its handler at `/_escrow/` on the listener's mux, wrapped only in `upstream.Recover`: the Host check, the tokens and the filters of the MCP routes are not in its chain. The escrow gets the listener's `RemoteFunc`, the same that the request log uses, so behind a proxy its client address is the right-most `X-Forwarded-For` entry outside `trustedProxies`. `Gate.Run` runs the sweep loop until shutdown. With `escrow.tcp: false` the handler is not mounted on the listener's mux.

With `escrow.socket`, `gate.New` builds a second `http.Server` whose mux holds only the escrow route, with `escrow.ConnContext` as its `ConnContext`: for each accepted `*net.UnixConn` it reads the peer's user ID (`SO_PEERCRED` in [`peer_linux.go`](../../internal/escrow/peer_linux.go), `LOCAL_PEERCRED` in [`peer_darwin.go`](../../internal/escrow/peer_darwin.go), none elsewhere) into the connection's context. On Linux it also takes the peer's process ID from `SO_PEERCRED` and walks the parent IDs in `/proc/<pid>/stat` (`outsideGateTree`); reaching the gate's own PID, or failing to read a step, marks the peer as inside the gate's tree, so hidden `/proc` entries fail closed. `escrow.OthersProcVisible` probes `/proc/1/stat`, and `gate.New` warns when it fails while `allowUIDs` is set. macOS does not check the tree. The handler finds the result there: a request with a peer is a socket request, its client address is `unix:uid=<n>`, and an allowed user ID outside the gate's tree skips the key check. A TCP connection never carries the value, so the listener always needs the key. `Gate.Run` opens the socket with `escrow.ListenSocket` before starting the servers: it creates the parent directory 0700 if missing and checks its owner and mode, removes a stale socket only when a dial to it is refused, binds in a private 0700 directory beside the target, `chmod`s there and renames the socket into place, so it never exists at the path with the umask's mode. Shutting the socket server down closes the listener, which removes the file. Keyless requests skip the failed-auth limiter, whose bucket is keyed by user ID only.

Each server's `proxy.Redaction` gets a `proxy.ReplacerFunc`: for every call the mirror builds a `proxy.Request` (method, name, and the arguments decoded once, lazily) and asks for a replacer, which with the escrow on and the server's `redact.escrow` true is `Escrow.Replacer` with the server's name and `redact.escrowTTL`; otherwise the plain marker. Progress messages and logged texts use `redact.Marker` directly, so they never create entries.

A server with `redact.files` gets a `filescan.Scanner` as `proxy.Options.Files`, with `Escrow.KeepFile` as its keeper when the escrow is on for the server; without a keeper it withholds with `[REDACTED:file]`. `Mirror.callTool` runs it on the redacted result, with the time taken just before the call was forwarded; an error withholds the result like a redaction failure, and the number of withheld files is added to the audit line's redactions.

## Store

`store` is a map from handle to entry under one mutex, plus a map from a dedup key (server, kind, SHA-256 of the value) to handle. Eviction scans for the oldest entry, which is linear in the entries; `escrow.maxEntries` is capped at 100000 to keep that cheap. Values are cleared with `clear` when an entry goes, as a best effort. The source summary of an entry copies the call's arguments named in `escrow.sourceArguments` (`Options.SourceArguments`, by default `DefaultSourceArguments` in [`summary.go`](../../internal/escrow/summary.go)), with the size and type limits fixed in code. File entries hold no content: they record the resolved root, the path below it, the size and the SHA-256, and `readFile` opens the root again with `os.OpenRoot`, opens the file with `O_NOFOLLOW|O_NONBLOCK`, and serves it only if it still matches.

## Failed-auth limit

`limiter` keeps a token bucket per client (an IPv6 address counts by its /64): 20 tokens, one more every 3 seconds, and a presented wrong key spends one. A request without a key costs nothing, so a web page that fires requests at a local listener cannot lock the owner out. A client with less than one token gets 429 before its key is looked at, so that a lucky guess is refused too. The table holds at most 4096 clients; a new one replaces the bucket with the most tokens, so a client that never failed is never in it. A client that rotates addresses gets a fresh budget with each one, so a global bucket (100 tokens, one more every second) bounds all of them: a wrong key from a client that is not trusted spends one, and while it is empty a request that presents a key from a client that is not trusted gets 429. A client is trusted for 24 hours after it presented the right key, in a table of at most 256 that drops the oldest; a trusted client's wrong keys spend only its own bucket. The limit slows guessing and keeps the log readable, while the key's length is what protects it; the price of the global bucket is that someone guessing at about one request a second can lock out every owner address that is not trusted: a new one, and, since trust is kept in memory only, all of them after a restart or a day without a successful request, until the guessing stops. A keyless socket peer is never locked out. Trust belongs to the client key, so whoever shares the owner's IPv4 address (a NAT) or IPv6 /64, or can name it in `X-Forwarded-For` through a trusted proxy, shares it too; such a client is still held to its own bucket. Behind a proxy on loopback, every local process can name its own address in `X-Forwarded-For`; keep agents off the trusted peer, or narrow `trustedProxies` to the proxy's own address. Devices that share an IPv6 /64, such as a home LAN, share one budget.

## File scanning

`candidates` (at most 64 per call) walks the structured content, JSON text content and the arguments for path members, takes `file://` URIs and resource URIs, and matches "downloaded to" in text; an unquoted path there is extended over the rest of its line (at most 4096 bytes) to the longest prefix, of at most 16 words, that lies under a root as written and names a regular file (`unquotedPath`). The budget is per call, across all content items: collecting stops, and the result is withheld, once more than 64 paths or 64 mentions are found or 1024 lookups are spent, so an adversarial result costs a bounded number of `stat` calls. `Scanner.open` resolves symlinks with `filepath.EvalSymlinks`, finds the root that contains the result (roots are resolved on every call, so a download directory created after the start works), opens it through `os.Root` and checks the opened file: regular, one link, and for a path only the arguments name, inode change time (`ctime`, which a writer cannot set) at or after the call. A path the result names may be older, since download tools that cache report the same file again, also across a restart. Only a file whose ctime is at or after the gate's start (`Options.Started`, less 2 seconds of slack for the coarse ctime clock) is kept in the escrow; an older one with secrets is withheld with the plain `[REDACTED:file]` marker. A clock stepped back (by NTP, say) by more than the slack makes files written after the start look older, so they are withheld without being kept, never passed. `Scanner.scan` reads at most `maxBytes` into memory, two scans at a time process-wide, hashes it, and runs `Engine.RedactString` with a replacer that only records kinds. `withhold` copies what it changes, so the downstream's result is never modified.

The platform-specific part, the link count and the inode change time, is in `stat_linux.go` and `stat_darwin.go`.
