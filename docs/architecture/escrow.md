# Escrow and file scanning

[Docs](../README.md) / [Architecture](README.md) / **Escrow and file scanning**

The escrow keeps redacted secrets in memory so that the owner can release them, and file scanning withholds downloaded files that hold secrets. The behaviour is specified in [`openspec/specs/escrow/spec.md`](../../openspec/specs/escrow/spec.md) and [`openspec/specs/file-scanning/spec.md`](../../openspec/specs/file-scanning/spec.md).

## Wiring

`cmd/mcp-gate serve` and `check` call `escrow.ResolveKey` ([`key.go`](../../internal/escrow/key.go)) with the config's `escrow.keyHash` or `escrow.keyHashFile` and the environment: it parses every source that is set (the file is opened once, checked with `fstat` and read up to 1 KiB), fails when two disagree, and returns the hash with the name of the source that wins (config, `MCP_GATE_ESCROW_KEY_SHA256`, then the deprecated `MCP_HUB_ESCROW_KEY_SHA256`). `serve` logs the deprecation warning, strips both variables from the environment the children inherit from, and passes the `escrow.Key` as `gate.Options.EscrowKey`. `gate.New` then builds one `escrow.Escrow` and mounts its handler at `/_escrow/` on the listener's mux, wrapped only in `upstream.Recover`: the Host check, the tokens and the filters of the MCP routes are not in its chain. The escrow gets the listener's `RemoteFunc`, the same that the request log uses, so behind a proxy its client address is the right-most `X-Forwarded-For` entry outside `trustedProxies`. `Gate.Run` runs the sweep loop until shutdown. With `escrow.tcp: false` the handler is not mounted on the listener's mux.

With `escrow.socket`, `gate.New` builds a second `http.Server` whose mux holds only the escrow route, with `escrow.ConnContext` as its `ConnContext`: for each accepted `*net.UnixConn` it reads the peer's user ID (`SO_PEERCRED` in [`peer_linux.go`](../../internal/escrow/peer_linux.go), `LOCAL_PEERCRED` in [`peer_darwin.go`](../../internal/escrow/peer_darwin.go), none elsewhere) into the connection's context. On Linux it also takes the peer's process ID from `SO_PEERCRED` and walks the parent IDs in `/proc/<pid>/stat` (`outsideGateTree`); reaching the gate's own PID, or failing to read a step, marks the peer as inside the gate's tree, so hidden `/proc` entries fail closed. `escrow.OthersProcVisible` probes `/proc/1/stat`, and `gate.New` warns when it fails while `allowUIDs` is set. macOS does not check the tree. The handler finds the result there: a request with a peer is a socket request, its client address is `unix:uid=<n>`, and an allowed user ID outside the gate's tree skips the key check. A TCP connection never carries the value, so the listener always needs the key. `Gate.Run` opens the socket with `escrow.ListenSocket` before starting the servers: it creates the parent directory 0700 if missing and checks its owner and mode, removes a stale socket only when a dial to it is refused, binds in a private 0700 directory beside the target, `chmod`s there and renames the socket into place, so it never exists at the path with the umask's mode. Shutting the socket server down closes the listener, which removes the file. Keyless requests skip the failed-auth limiter, whose bucket is keyed by user ID only.

Each server's `proxy.Redaction` gets a `proxy.ReplacerFunc`: for every call the mirror builds a `proxy.Request` (method, name, and the arguments decoded once, lazily) and asks for a replacer, which with the escrow on and the server's `redact.escrow` true is `Escrow.Replacer` with the server's name and `redact.escrowTTL`; otherwise the plain marker. A replaced JSON member name is the marker with `#2`, `#3` and so on appended when the object already has that name, so a consumer that parses markers should allow that suffix. A token split across two JSON strings reaches the replacer once, whole, for its first part; the second part is `redact.ContinuationMarker`, which is not kept. A consumer restores a text as the escrow spec defines: each marker with a known handle becomes its value and each continuation marker is dropped. Progress messages and logged texts use `redact.Marker` directly, so they never create entries.

`Escrow.Replacer` returns an `escrow.Replacer`, one per call: the mirror's `call` asks for it once and keeps it. It remembers the marker it issued for each kind and value, so a repeat gets it without a second insert and each handle is recorded once; `Issued` returns a replacer that only looks those up and leaves any other finding as it is, which the file scan uses to redact paths without keeping anything. Every entry it creates carries its `batch`; a dedup hit from another replacer clears that, because another result now shows the handle. When a later stage withholds the result, `call.withheld` calls `Discard` (through `proxy.Discarder`), which removes the entries among the replacer's handles that still carry its batch, so a withheld result's findings do not use the store's capacity until their TTL. Entries that held the value before, or whose handle another result shows, stay.

Handles are stable per server, kind and value, as the mcp-proxy escrow's are, and the owner's consumer relies on that to restore texts across turns. That makes the handle an equality oracle: a client that can make a server return text of its choosing learns, by comparing handles, whether a guess equals a secret the server returned before. That recovers low-entropy values (PINs, short passwords) by trying candidates. The store bounds it only loosely: every wrong guess is a new entry, eviction takes the oldest by `created`, so about `escrow.maxEntries` wrong guesses evict the target, and its next sighting gets a new handle.

A server with `redact.files` gets a `filescan.Scanner` as `proxy.Options.Files`, with `Escrow.KeepFile` as its keeper when the escrow is on for the server; without a keeper it withholds with `[REDACTED:file]`. The file scan stage of the request pipeline (`scanFiles`) runs it with the result the server returned (kept by the pipeline as `exchange.downstream`), the redacted result, the call's replacer, and the time taken just before the call was forwarded: paths are looked for in the server's result, since redaction can turn part of a path (a directory name that looks like a token) into a marker, and are withheld from the redacted one; an error withholds the result like a redaction failure, and the number of withheld files is added to the audit record's redactions.

## Store

`store` is a map from handle to entry under one mutex, plus a map from a dedup key (server, kind, SHA-256 of the value) to handle. Eviction scans for the oldest entry, which is linear in the entries; `escrow.maxEntries` is capped at 100000 to keep that cheap. Values are cleared with `clear` when an entry goes, as a best effort. The source summary of an entry copies the call's arguments named in `escrow.sourceArguments` (`Options.SourceArguments`, by default `DefaultSourceArguments` in [`summary.go`](../../internal/escrow/summary.go)), with the size and type limits fixed in code. File entries hold no content: they record the resolved root, the path below it, the size and the SHA-256, and `readFile` opens the root again with `os.OpenRoot`, opens the file with `O_NOFOLLOW|O_NONBLOCK`, and serves it only if it still matches.

## Failed-auth limit

`limiter` keeps a token bucket per client (an IPv6 address counts by its /64): 20 tokens, one more every 3 seconds, and a presented wrong key spends one. `allow` runs before the key is compared: a client with less than one token gets 429 for any request that presents a key, the right one included, so a lucky guess is refused too and guessing from one address is bounded at 20 plus one per 3 seconds. A request without a key costs nothing, so a web page that fires requests at a local listener cannot lock the owner out. The table holds at most 4096 clients; a new one replaces the bucket with the most tokens, so a client that never failed is never in it. Whoever shares the owner's address shares its bucket and can empty it: devices behind one NAT or IPv6 /64, and every client behind a same-host reverse proxy when `behindProxy` is off, which `gate.New` warns about at start (escrow on a loopback listener without `behindProxy`). After the compare, `fail` also spends a global bucket (100 tokens, one more every second) for clients rotating addresses, unless the client presented the right key in the last 24 hours (`trusted`, at most 256, the oldest dropped); while it is empty a wrong key gets 429 instead of 401 and still spends its client's token. The global bucket only sheds wrong-key load and never refuses the right key, so it cannot lock anyone out. None of this is the protection: a key of at least 128 random bits (`openssl rand -hex 32` gives 256) is. Behind a proxy on loopback, every local process can name its own address in `X-Forwarded-For`; keep agents off the trusted peer, or narrow `trustedProxies` to the proxy's own address.

## File scanning

`candidates` (at most 64 per call) walks the structured content, JSON text content and the arguments for path members, takes `file://` URIs and resource URIs, and matches "downloaded to" in text; an unquoted path there is extended over the rest of its line (at most 4096 bytes) to the longest prefix, of at most 16 words, that lies under a root as written and names a regular file (`unquotedPath`). The budget is per call, across all content items: collecting stops, and the result is withheld, once more than 64 paths or 64 mentions are found or 1024 lookups are spent, so an adversarial result costs a bounded number of `stat` calls. `Scanner.open` resolves symlinks with `filepath.EvalSymlinks`, finds the root that contains the result (roots are resolved on every call, so a download directory created after the start works), opens it through `os.Root` and checks the opened file: regular, one link, and for a path only the arguments name, inode change time (`ctime`, which a writer cannot set) at or after the moment the call was forwarded, less the same 3 seconds of slack as below: `ctime` comes from the kernel's coarse clock and some filesystems truncate it (FAT to 2 seconds), while the forward time comes from the fine clock, so without it a file written just after the forward would look older and pass unscanned. A path the result names may be older, since download tools that cache report the same file again, also across a restart. Only a file whose ctime is at or after the gate's start (`Options.Started`, the time the `Gate` was built, which a reload that rebuilds the scanner keeps; less 3 seconds of slack for the coarse ctime clock) is kept in the escrow; an older one with secrets is withheld with the plain `[REDACTED:file]` marker. A clock stepped back (by NTP, say) by more than the slack makes files written after the start look older, so they are withheld without being kept, never passed. The forward check has no such fallback: a clock stepped back by more than the slack during a call, or a root on a network filesystem whose server clock runs more than the slack behind the gate's (the server sets `ctime` there), makes a file only the arguments name look older than the call, and it is not scanned. `Scanner.scan` reads at most `maxBytes` into memory, two scans at a time process-wide, hashes it, and runs `Engine.RedactString` with a replacer that only records kinds. Every candidate is scanned before any file is kept, so a call whose last file cannot be scanned keeps none. `withhold` replaces a content block of the redacted result when it, or the server's block at the same index (redaction keeps blocks one for one), names a path; a block the path was found in (`candidate.blocks`, which also covers JSON text that escapes it) is replaced too, and the scan withholds the whole result when the two results have different numbers of blocks. Strings in structured content and `_meta` are matched against the path as reported, cleaned and resolved, and against each of these redacted with the call's replacer's `Issued` lookup, which gives a finding the marker it got in the result and keeps nothing new; each of these forms is also matched as JSON may escape it (`jsonForms`: `\/`, `\uXXXX` in either case, both, and `encoding/json`'s own escaping), so an escaped mention in any block or string is found by its content. It copies what it changes, so neither result is modified.

The platform-specific part, the link count and the inode change time, is in `stat_linux.go` and `stat_darwin.go`.
